The counter ABI now runs a pinned, unmodified Linux 6.12 `perf stat` in attached,
non-inheriting mode. A real KVM PMC was forced across its advertised 48-bit width;

This follows the [scoped/remote checkpoint](W4.2_REMOTE_RESULTS.md). Intel event

Native Intel/AMD measurements remain additional hardware coverage.

The recorded W4.2 kernel below is an immutable historical checkpoint. The

## Stock Linux tool

`tools/linux/perf.mk` checksum-pins the official Linux 6.12 archive and builds
upstream `tools/perf` statically with musl. No upstream source is patched. Optional
recording, unwind, UI and event-database dependencies are disabled; see the recipe
for exact options. `WERROR=0` permits warnings from the pinned source on GCC 16.
The output has no ELF interpreter. This is an optional port, outside default
images; `perf-install` stages the binary into the selected `DESTDIR`.

```sh
make -C tools/linux perf-static
make -C tools/linux perf-install
# Inside AzamiOS, replace TID with a busy, live Linux thread ID:
perf stat --no-inherit -e task-clock:u -t TID --timeout 300
perf stat --no-inherit -e instructions:u -t TID --timeout 300
perf stat --no-inherit -e rC0:u -t TID --timeout 300
```

The upstream [stat counter configuration](https://github.com/torvalds/linux/blob/v6.12/tools/perf/util/stat.c)
and an actual traced request established the required ABI: 136-byte attributes,
zero sampling period, `PERF_SAMPLE_IDENTIFIER`, disabled, exclude-kernel/HV/guest,
TOTAL_TIME_ENABLED/RUNNING, a TID with CPU -1, and FD_CLOEXEC. IDENTIFIER is inert
record-layout metadata when no samples are generated. `exclude_guest` is satisfied
because AzamiOS has no guest execution domain. Nonzero periods, other sample
layouts and `exclude_host` still return EOPNOTSUPP. Tests cover those boundaries.

Linux-style `/sys/bus/event_source/devices` now describes the actual sources:
`software/type` is 1; a usable PMU also exposes `cpu/type` as 4, its online CPU
list, and `format/{event,umask,edge,inv,cmask}` matching the accepted raw config
bits. CPU PMU discovery disappears when unavailable. Before this change stock
perf silently fell back to default events when its event-source scan failed;
the new runner requires an exact requested-event CSV row with a positive count
and running percentage, as well as successful child exit. The shared parser
requires finite positive count/runtime and a running percentage between zero
(exclusive) and 100 (inclusive). Corrupt, nonfinite and mismatched rows are rejected.

KVM runs reported positive task-clock, instructions and raw-instructions counts
with 100% running time. TCG runs reported a positive software clock and explicitly
skipped unavailable hardware. The CLI uses `-vv` in the runner to preserve actual
attributes and FD results; verbose output is recorded in the saved guest log.

## Counter width and filters

`azami.pmu_selftest=1` opts into a bounded BSP boot test before scheduling/perf
users exist. It acquires an instructions slot, writes the disabled counter to
its enumerated mask minus 4095, re-enables it without the overflow interrupt bit,
and reads around 65,536 iterations of a four-instruction assembly loop. The test
uses the production slot reader and the same `pmu_counter_delta` helper as normal
perf accounting. It releases/synchronizes the slot, zeroes the touched counter,
and clears the touched Intel overflow status bit. Normal boots perform no test;
unavailable PMUs/instructions produce an explicit PMUSKIP record. No userspace
counter-write API was introduced.

| Advertised width | Before | After | Recovered interval |
| --- | --- | --- | --- |
| 48 bits | 281474976706572 | 258083 | 262167 |

This is an observed crossing of KVM's virtual PMC width backed by host PMU
counting, not a claim of native physical-counter overflow or PMI delivery.
The test runner requires exactly one full-serial result and independently checks
the width, crossing and modulo subtraction. The pure production-code test also
covers arithmetic widths 32–64 and all 128 Intel architectural unavailability
masks, including unsupported AMD aliases. It does not execute privileged MSRs.

The runtime fixed user loop counted 800136 user instructions, 2252 kernel
instructions and 800031 raw-alias instructions. A subsequent 20,000-getpid loop
counted 60084 user instructions and 4700760 kernel instructions. The checks
require user/kernel separation, positive kernel work, a close raw/generic alias
match and frozen disabled totals. Console and clock calls are outside the fixed
loop. These counts establish filter behavior on the recorded PMU, not native
performance comparisons or exact instruction attribution at syscall boundaries.

Inheritance, enable-on-exec, groups, multiplexing, sampling and `perf record`
remain unsupported. The default `perf stat command` workflow requires inheritance/
exec handling and is not claimed. Native/vendor runtime coverage can extend this
checkpoint; W4.3 can now use the supported attached counting mode for measured
kernel improvements. Sampling/recording remains a separate later milestone.
