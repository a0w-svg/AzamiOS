# W3.8 Rename Semantics and Flag Checkpoint — 2026-10-06

AzamiOS now implements Linux-compliant `renameat2(2)` along with full POSIX/Linux semantic fidelity for `rename(2)` and `renameat(2)` across tmpfs and ext2 filesystems.

### 1. Architectural Changes & Semantics

1. **`renameat2` System Call & Flag Handling:**
   - Dispatches `SYS_rename` (82), `SYS_renameat` (264), and `SYS_renameat2` (316) through unified kernel routing with strict flag validation.
   - Supports `RENAME_NOREPLACE` (1U << 0) and `RENAME_EXCHANGE` (1U << 1).
   - Enforces flag exclusivity: rejects `RENAME_NOREPLACE | RENAME_EXCHANGE` and unknown/unsupported flag bits with `-EINVAL`.
   - Rejects `RENAME_WHITEOUT` with `-EINVAL` until union/overlay whiteouts are supported.

2. **`RENAME_NOREPLACE` Atomicity:**
   - Guaranteed atomic non-replacement: if the target name exists (regular file, directory, or symlink), returns `-EEXIST` (errno 17).
   - Same-file / hardlink self-rename with `RENAME_NOREPLACE` returns `-EEXIST`, matching Linux.

3. **`RENAME_EXCHANGE` Atomicity:**
   - Atoms-level exchange of directory entries across files, directories, and symlinks without intermediate unbound states.
   - Cross-directory exchange correctly updates parent dentry pointers, `..` (dotdot) directory references, and parent link counts.
   - Enforces bidirectional descendant hierarchy validation: swapping a directory with its own descendant returns `-EINVAL`.
   - Missing source or destination returns `-ENOENT`.

4. **Path Traversal & Trailing Slash Semantics:**
   - Preserves trailing slash semantics during normalization and directory lookup.
   - Operations that do not follow final symlinks (`follow_final == false`, such as `rename`, `unlink`, `rmdir`, `lstat`) strictly enforce that a trailing slash requires a true directory; a trailing slash on a symbolic link (even pointing to an existing directory) returns `-ENOTDIR` (errno 20).
   - Moving a regular file onto a path with a trailing slash (`rename("f", "target/")`) fails with `-ENOTDIR`.
   - Trailing slash on an existing directory is accepted and preserved.

5. **POSIX Special Names (`.` and `..`):**
   - Renaming `.` or `..` as source or destination returns `-EBUSY` (errno 16) whenever the referenced directory exists.
   - If the parent of a `.` or `..` path does not exist (e.g., `"missing/."`), returns `-ENOENT` (errno 2).

6. **Type Mismatch & Cross-Device Restrictions:**
   - Moving a directory onto a non-directory returns `-ENOTDIR` (errno 20).
   - Moving a non-directory onto a directory returns `-EISDIR` (errno 21).
   - Moving a directory onto a non-empty directory returns `-ENOTEMPTY` (errno 39).
   - Moving a directory onto an empty directory replaces the empty directory and decrements the target parent's link count.
   - Cross-filesystem rename returns `-EXDEV` (errno 18).

7. **Concurrency & Thread Safety:**
   - All directory mutations and dcache re-identifications execute under the VFS namespace topology guard.
   - Concurrent `RENAME_EXCHANGE` race test (2,000 iterations between competing worker threads) completed with zero corrupted states and verified atomic swaps.
