# W4.1 execution record — 2026-10-06

W4.1 is implemented and validated on Linux-host and AzamiOS under TCG.
`tests/bench` contains four real static musl workloads, a shared checked timer
interface, a process supervisor, and a disposable guest/Linux runner. Each
default baseline completed one discarded warm-up round and ten measured rounds
(44 supervised children, 55 samples including warm-ups). Every result, EOF,
child exit, content checksum, and positive duration was checked.

The source revision at measurement was
`9f9c2fea68ec6b450becf88357cd0b5c81e8dce3`, with uncommitted milestone sources.
The complete manifests retain each run's dirty-tree fingerprint and source
inventory; all five payload hashes match between guest and Linux. The kernel
SHA-256 was
`416ef34df27742177413fb3c0e026d1802d7f22487b8aa3197ec526cc1ff8cf3`.
No kernel optimization was applied in this milestone.

The guest used QEMU 10.2.2, q35, multi-threaded TCG with a 512 MiB translation
cache, `max,+rdrand,+rdseed`, four vCPUs, 1536 MiB RAM, and BIOS boot. It reported
`CLOCK_MONOTONIC` resolution of 10 ns. The Linux-host comparison reported an
AMD Ryzen 7 8845HS CPU, kernel `7.2.8-200.fc44.x86_64`, and 1 ns resolution.
The suite used stock musl and `-std=c11 -O2 -g -Wall -Wextra -Werror -static`.
Compiler identity, host load/affinity, firmware/image hashes, full commands,
and exact workload counts are saved in the manifests.

| Workload | Unit | AzamiOS TCG median | TCG IQR | Linux-host median | Linux IQR |
| --- | --- | ---: | ---: | ---: | ---: |
| 10,000,000 raw getpid calls | ns/call | 385.87 | 26.85 | 253.46 | 2.72 |
| 10,000 pipe request/reply round trips | µs/round trip | 56.73 | 7.09 | 6.49 | 0.46 |
| 256 MiB sequential mapping + first touch | logical MiB/s | 542.50 | 238.78 | 1753.44 | 206.54 |
| 256 MiB shuffled mapping + first touch | logical MiB/s | 444.94 | 258.68 | 2027.61 | 490.43 |
| 1,000 fork/waitpid iterations | forks/s | 2154.90 | 257.13 | 12247.03 | 3392.12 |

IQR is the inclusive 75th percentile minus the 25th percentile. Raw durations,
min/max, and median absolute deviations are also retained. These measurements
are separate compatibility/performance baselines, not an equal-hardware OS
comparison. TCG memory spread is substantial; no physical CPU speedup or
optimization benefit is claimed. Future comparisons need matched workload and
machine settings and an improvement larger than the observed noise.

The memory workload revealed an important difference in existing behavior:
AzamiOS allocates anonymous pages eagerly in `sys_mmap_impl`, whereas Linux
commonly allocates on first write. A first-touch-only timer would omit AzamiOS's
allocation cost. The benchmark therefore retains mapping and touch durations
separately and uses their sum for its logical provisioning rate. In the TCG
sequential run the median mapping duration was 463.45 ms and the median touch
duration was 9.70 ms (component medians need not add to the median total).
The benchmark does not count actual page faults or measure streaming bandwidth.
This measurement correction is part of W4.1; changing kernel mapping policy
remains later work.

**KVM follow-up — 2026-10-06:** the host device works outside the sandbox
(API 12). The W3.8 path checkpoint passes all four KVM boot configurations,
in addition to six TCG configurations. Its new KVM benchmark baseline uses the
updated kernel and is recorded in [W3.8_OPENAT2_RESULTS.md](W3.8_OPENAT2_RESULTS.md).
The earlier skip artifacts remain historical evidence; they do not describe
current host KVM availability.

All test disks were created under `build/`; `hdd.img` was not rebuilt or
attached. PMU counting/sampling and physical-hardware performance were outside
this milestone. See [the suite README](../tests/bench/README.md) for reproduction,
data format, and timeout/cleanup behavior. The next milestone is W3.8: path,
exec, and isolation fidelity, with security defects taking precedence.

Raw run logs and complete source-snapshot manifests are retained locally in
ignored evidence directories; they are not included in the source checkout.
The documented commands regenerate these artifacts.
