# W4.3 user-copy I/O timing — 2026-10-12

This checkpoint adds a repeatable small/large-transfer baseline after the
[user-copy transaction fixes](W4.3_USERCOPY_FIX_RESULTS.md). A static-musl
payload runs unchanged on Linux and four-vCPU KVM/TCG guests. It pins its single
worker to the first available CPU and measures memfd write/read pairs for
16, 64, 256, 4096, 65536 and 1048576 bytes.

Each pair seeks to zero, writes, seeks to zero and reads the same size. The
payload checks exact transfer lengths, seek results, endpoint bytes and source/
destination canaries during the loop; full data comparison and byte checksum
follow outside the timed interval. Source/destination pages are touched and
four pairs warm each size before measurement. There is one discarded full
round followed by ten measured rounds. Iterations per size are
`min(4096, max(4, 4194304 / size))`: 4096, 4096, 4096, 1024, 64 and 4.

The recorded interval includes four syscalls per pair, user checks, filesystem
work, kernel scratch-buffer allocation where applicable, and both user copies.
Logical MiB/s counts the requested write plus read bytes; it does not count all
internal memory traffic. Repeated transfers reuse warm buffers. This workload
does not isolate `rep movsb`, page-fault latency or physical memory bandwidth.
No copy threshold or SIMD policy changes accompany this baseline.

## Results

All 66 records pass on Linux, KVM and TCG. The immutable kernel is the one
validated by the user-copy fix gates: 121 ABI checks, three smoke groups,
21 FD-lifetime and 109 epoll checks per accelerator, and all ten boot cases.
The new workload builds with `-Wall -Wextra -Werror`; parser tests reject 28
corruptions for each runtime and confirm that slow warmups do not affect
statistics. Injected interior-data and guard corruption both fail with a
nonzero exit. `make -C tests/bench all check` also passes all 15 existing
runner tests. No kernel implementation changed for this timing checkpoint.

The [compact evidence](../tests/bench/results/2026-10-12-usercopy-timing.json)
contains all 198 raw durations, derived logical rates, compiler flags/version,
payload/source/kernel hashes, CPU affinity, timer resolution and host load.
The host is an AMD Ryzen 7 8845HS; its starting load average was
1.875/1.991/2.060. Linux and both guests select affinity CPU zero.
Raw logs and images remain in `/tmp/azami-usercopy-timing-final/`. The larger
KVM samples show appreciable spread; repeated baselines are required before
attributing a change to an implementation.

## Reproduction

```sh
make -C tests/bench all
python3 -B tests/bench/usercopy_run.py --accel kvm tcg \
    --kernel build/kernel.elf --output /tmp/azami-usercopy-timing
python3 -B tests/bench/test_usercopy_run.py /tmp/azami-usercopy-timing/linux.txt
```

The runner copies the payload and kernel before execution, records their hashes
and the probe source/build configuration, and requires all 66 named samples,
exact counts, checksums, intact canaries and a successful final verdict. It
saves raw durations plus median, min/max and MAD for ten measured samples at
each size; the discarded round is retained separately. Linux, KVM and TCG
results remain distinct. A requested unavailable accelerator is a failure or
explicit skip, never a passed measurement.

These timings can detect regressions under the same workload and VM setup.
They cannot establish a Linux-versus-Azami speedup on equal hardware. TCG is
execution/regression evidence; KVM still includes virtualization and host load.
Cold buffers, multiple concurrent workers, positional-I/O fidelity, mapping/COW
races and native hardware are separate follow-ups.
