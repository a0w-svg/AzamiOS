# W4.2 thread counter checkpoint — 2026-10-07

Subsequent [scoped/remote results](W4.2_REMOTE_RESULTS.md) validate the remote
requests and task/CPU scopes listed as remaining below. This document preserves
the first checkpoint's scope and measurements.

The first W4.2 checkpoint implements accurate local thread counting. W4.2
remains in progress; CPU-scoped and other-task attachment and bounded remote
hardware access remain the next checkpoint. No optimization or sampling support
is claimed.

Changes:

- Events attach to the calling thread (`pid=0` or its explicit TID, `cpu=-1`).
  Scheduler and resolved page-fault hooks charge occurrences only while enabled.
  CPU/task clocks use scheduled `ktime_get_ns()` intervals. Enabled and running
  times use task context time, excluding sleep; with no multiplexing they agree.
  Disabled values/times freeze; enabling resumes; RESET clears the value and
  preserves times. Thread retirement freezes the final readable event.
- Processes and sibling threads now allocate IDs from one shared PID/TID space.
  Separate allocators previously collided, causing unrelated idle execution to
  appear in thread counters. Events additionally match both process and thread
  IDs, retain no borrowed task pointer, and stop matching at retirement.
- A new counted `proc_get_by_tid()` owner lookup checks positive target IDs
  without retaining a borrowed thread pointer. Current other-task attachment
  returns `EOPNOTSUPP` after target/credential validation.
- Hardware deltas remain width-masked and are read on the CPU owning their
  interval. Live reads/control that would require a remote raw PMU read return
  `EOPNOTSUPP`. An unrelated PMU slot change no longer resets existing counters.
  Raw selectors cannot inject privilege, enable, or interrupt bits. Intel events
  beyond CPUID's enumerated availability vector are unavailable; bus cycles no
  longer masquerade as reference cycles. AMD cache mappings remain unsupported.
- `/proc/sys/kernel/perf_event_paranoid` defaults to 2. Signed integer reads and
  writes are implemented with bounded parsing; writes require `CAP_SYS_ADMIN`.
  Event checks use effective `CAP_PERFMON`/`CAP_SYS_ADMIN`, without an unconditional
  root/PID exemption. Dropping capabilities still restricts root callers.
- Known unsupported attributes return explicit errors. Struct reads are bounded
  to one page; invalid sizes/extensions return `E2BIG` and write back size 136.
  Sampling, groups, inheritance, and enable-on-exec are rejected. `FD_NO_GROUP`
  validates its leader FD before creating an independent event. Counting FDs
  report Linux's no-ring `POLLHUP`; reads remain available. Ioctl encodings,
  buffer sizes, ID values, dup/close, fork, exec, and CLOEXEC are tested.

The static stock-musl probe is [tools/linux/tests/perf.c](../tools/linux/tests/perf.c).
It runs unchanged on Linux and AzamiOS. It includes four concurrent workers
performing 600 open/dup/enable/reset/read/disable/close sequences; a thread sleeping
while a sibling works; COW faults from genuinely shared fork pages; CPU migration;
16 child lifetimes while a sibling holds a live TID; and frozen post-exit reads.
The hardware test shares an instruction-counter slot between threads and checks
that the sleeping thread excludes the sibling's busy-loop instructions. It also
opens a distinct cycles slot while the instruction event remains enabled.

Remaining W4.2 work:

1. Bounded cross-CPU PMU requests with safe timeout/cancellation ownership. The
   existing `smp_call_function*` waits indefinitely and cannot provide this yet.
2. CPU-scoped/system-wide and other-task attachment, including remote live reads,
   remote control, target exit races, and permission coverage for other credentials.
3. Additional hardware event/filter/wrap coverage on appropriate CPU vendors,
   and stock `perf stat` compatibility after checking its requested ABI features.
   Current masks handle wrap arithmetically; an induced real hardware wrap and
   broad privilege-filter behavior have not been measured.

Inheritance, enable-on-exec, groups, multiplexing, and sampling remain explicit
unsupported features. Software page-fault counts currently cover successfully
resolved COW/demand faults; no major-I/O-fault source exists. Alignment/emulation
fault events return `ENOENT`. This checkpoint does not establish complete Linux
perf semantics, availability on every PMU, or physical-hardware performance.
