# W4.3 allocator exhaustion checkpoint — 2026-10-11

The opt-in boot test now exercises real physical-memory allocation failures,
orders 0–9 in zeroed/general/DMA32 batches, and remote per-CPU cache retention.
Allocation policy and cache sizes are unchanged. The [compact results](../tests/bench/results/2026-10-11-pmm-selftest.json)
record the tested kernel and allocator hashes; raw logs remain local.

The test runs after timekeeping and bounded RPC initialization, before scheduler
activation. APs are parked with interrupts enabled. There are no competing
scheduler, driver or user allocations. It requires one to four contiguous online
CPUs and 128 MiB–2 GiB of managed RAM; other configurations explicitly skip.
Fixed ownership bookkeeping adds 64 KiB of BSS. Disabled boots do not allocate,
drain caches or issue test RPCs.

Thirty mixed-order allocations verify alignment, nonoverlap, all zeroed bytes
in the first batch (4,190,208 bytes), and both edges of every page. All blocks
are freed with their original orders in a shuffled permutation. Both capacity
and every per-zone/per-order buddy count must return to the initial snapshot.

Exhaustion then allocates from order 18 down to zero using the public API. All
nineteen orders reach a real allocation failure; the actual successful-order
mask is recorded. The 4,096-record bound is an explicit failure if reached, not
an exhaustion verdict. Held-page edges are checked before cleanup.

On four CPUs, one individually allocated page is freed into CPU1's initially
empty cache before pressure. Exhaustion reaches zero buddy pages and zero BSP
cached pages. A BSP order-zero allocation fails while CPU1 retains that one
free page. An owner-side drain returns it to the buddy; the identical public
allocation then returns exactly that page. With it held, global exhaustion is
also verified. The one-CPU control exhausts all free pages and marks remote
coverage unsupported. Final cleanup restores every page and buddy-order count.

All eight configurations passed the five ordered PMM records and the following
121-assertion ABI probe. The final kernel also passed all ten normal-boot
BIOS/UEFI KVM/TCG configurations with the selftest disabled. Dropping CPU1 RPC
handling produced a bounded panic before pressure, with `rc=-110` and no
success/ABI verdict. An eight-CPU guest explicitly skipped and completed the
ABI probe; the evidence validator rejected that skip as selftest success.
Thirteen corrupted real-log variants were rejected for each single/multiple-CPU
profile, including missing/repeated phases, invalid arithmetic and missing ABI.

The fault test exposed unsigned formatting of signed panic arguments.
`kernel/panic.c` now reads the correct signed vararg width and handles minimum
negative values through unsigned magnitude arithmetic. Eleven hosted cases
compile the actual production formatter with platform stubs and UBSan trap
checks, comparing signed/unsigned boundaries and mixed arguments to `snprintf`.

Gemini reviewed the allocator and RPC source through Antigravity using the
approved tool-free export. Its claimed seed deadlock does not apply: the
callback owns the current CPU's cache with interrupts disabled, caching is
armed, and the empty-cache check proves that the public free cannot spill or
reacquire the global lock. Timeout payloads reside in the permanent RPC slot;
an ambiguous completion panics and never resumes with uncertain ownership.
The boot hook is invoked once; its seed acknowledgement also follows successful
RPC completion. Spin-budget cancellation, descriptor limits and expected OOM
messages remain explicit test limitations. Independent review found and fixed
an actual reporting defect: exhaustion totals now describe the snapshot before
remote recovery, so held pages plus cached pages equals initial capacity.

One earlier TCG batch had its ABI verdict interrupted by DHCP console output.
The strict runner rejected it; the raw failure remains local. Final PMM guests
disable their NIC to isolate the verdict from unrelated network logging.

This proves the retained-page failure on the tested pre-scheduler guests. It
does not establish concurrent allocator throughput, fragmentation recovery,
Normal-zone behavior above 4 GiB, or native hardware behavior. Refill/spill
performance remains unmeasured. Generic PMM callers can hold heap/VMM locks
with interrupts disabled, so synchronous remote RPC is not a safe drop-in
allocation-failure fix. The next allocator checkpoint should audit deferred,
nonallocating pressure notification and bounded owner-side reclaim, followed by
an explicit retry API for callers that can release and revalidate their locks.
User-copy boundary faults and concurrent COW/range shootdowns remain later work.
