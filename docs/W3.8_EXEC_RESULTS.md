# W3.8 interpreter and exec checkpoint — 2026-10-06

The ELF loader now opens the exact embedded `PT_INTERP` name in the caller's
filesystem view. It returns interpreter lookup, permission, header, program
header, segment-read, VMA allocation, and page-map failures. It no longer
substitutes a glibc, musl, or AzamiOS loader, or starts the main executable when
its required interpreter cannot load. Main executable and shebang interpreter
names also no longer receive implicit `.elf`, `/bin`, or `/sbin` alternatives.
Callers must pass a real pathname; userland remains responsible for PATH search.

Exec builds a detached image with its own page tables, VMA list/tree, heap,
mmap cursor, stack bounds, and vDSO mappings. Failure destroys only that image.
Successful exec stops and reaps siblings, closes CLOEXEC descriptors, releases
old shared-memory attachments, publishes the new metadata, switches address
spaces, and resets TLS/signal state. The live process's VMA registry is never
reset during image preparation. Kernel process spawning uses the same staging
and commit implementation before creating its first thread.

`PT_INTERP` lengths outside 2–4096 bytes or a missing final NUL return
`ENOEXEC`; short path/header reads return `EIO`; invalid interpreter ELF or
program headers return `ELIBBAD`. The canonical UAPI now includes Linux's
`ELIBBAD` value, 80. VFS errors such as `ENOENT`, `EACCES`, `ELOOP`, `ENOTDIR`,
and `ENAMETOOLONG` propagate. ELF class, byte order, machine, type, program
header size/count, address arithmetic, and inter-image collisions are checked.
Map/VMA allocation failures propagate rather than being ignored. A disabled
vDSO remains optional; failure to install an enabled vDSO fails image preparation.
Argument/environment vectors must copy completely: inaccessible pointers return
`EFAULT`, allocation errors return `ENOMEM`, and bounded storage overflow returns
`E2BIG`. Shebang names cut off by the parser are rejected rather than executed
as a prefix; excessive rewritten argument counts also return `E2BIG`.

The guest initrd deliberately contains a working musl interpreter at a former
fallback location. Missing requested interpreters still return `ENOENT`.
Fixtures also cover missing main/script interpreters, valid `.elf` alternatives
that must not be selected, a working interpreter path longer than 256 bytes,
relative lookup, malformed/truncated headers and paths, oversized PT_INTERP,
permission errors, symlink loops, and nondirectory components. Seven additional
AzamiOS failure/preservation pairs cover incompatible class/byte order, invalid
segment sizes, short segment reads, address overflow, image collisions, and
late argument-stack overflow after stack/vDSO mapping.

Those fourteen additional observations are explicitly excluded from the common
Linux comparison. Linux's validation and commit timing differ: some malformed
image errors happen after `begin_new_exec`, when returning to the old program
is no longer possible. AzamiOS eagerly stages mappings and can reject them
while preserving the caller. The class/byte-order checks and bounded argument
storage also remain explicit AzamiOS policy, not a claim of identical Linux
handling for every malformed ELF.

Remaining limits: VFS paths are still bounded to 512 bytes, program headers to
256, each argv/envp vector to 127 entries, each copied string to 1022 bytes,
and initial argument storage to one stack page. The shebang buffer is 128 bytes
and rewriting accepts at most 62 arguments. Executable checks require a regular
file and at least one execute bit; complete DAC/ACL, mount noexec, set-ID,
file-write exclusion (ETXTBSY), and execveat descriptor identity/nofollow
semantics need further work. This checkpoint tests failed exec with live threads;
it does not establish concurrent successful-exec or general signal/thread
conformance. The initial signal-delivery experiment failed through both `raise` and
process-directed `kill` after pthread exit; the kernel currently stores signal
masks at process scope. The suite checks process-directed handler delivery
before the threaded stress and verifies
handler/alternate-stack preservation independently. These signal limitations
were not changed here.

Allocation/map error paths were reviewed and now unwind the detached image;
physical-memory exhaustion was not injected. No performance improvement or
new benchmark baseline is claimed. No TLB retry appeared in the final exec,
path, namespace, futex, or boot logs; this does not supersede the prior
checkpoint's teardown diagnostic or establish a general SMP audit.
