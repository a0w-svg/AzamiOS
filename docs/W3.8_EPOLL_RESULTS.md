# W3.8 epoll wait and registration identity checkpoint — 2026-10-06

`epoll_wait`, `epoll_pwait`, and `epoll_pwait2` now share a counted-descriptor
wait implementation. It uses absolute monotonic nanosecond deadlines, preserves
positive fractional timeouts, and saturates valid enormous intervals instead
of overflowing into an immediate poll. The `epoll_pwait` mask and size now
come from the correct fifth and sixth x86-64 syscall arguments.

Interrupted masked waits keep the temporary mask through signal-handler
selection. Thread-local restoration bookkeeping transfers the original mask
into the signal frame; `rt_sigreturn` restores it after the handler. Successful,
timed-out, and failed waits restore the original mask directly. Masked waits
filter SIGKILL/SIGSTOP, enforce an eight-byte kernel signal set, and ignore the
size argument when the mask pointer is NULL. Epoll waits return `EINTR` even
when the handler requests `SA_RESTART`.

The shared signal-set representation now uses Linux's bit zero for signal one.
Pending delivery, kill/job control, ptrace injection, handler masks, sigreturn,
timed signal consumption, signalfd, and seccomp SIGSYS use the same conversion.

Epoll registration identity and modes now match Linux's open-file-description
model:
1. Registrations identify `(struct file *, int fd)` keys. When a file descriptor
   is duplicated via `dup()` or `dup2()`, both descriptors can be registered in
   the same epoll instance with distinct event masks and data tokens.
2. File description lifetime is tracked globally. When an individual descriptor
   pointing to a file description is closed, the remaining open descriptors for
   that description keep the epoll watch alive. When the underlying description's
   reference count drops to zero (`vfs_close_locked`), `epoll_file_closed()`
   automatically unregisters all instances watching that description.
3. Regular files and directories reject registration with `EPERM` (errno 1).
4. Self-registration and nested epoll cycles are detected and rejected with `ELOOP`
   (errno 40). Nested epoll readiness is supported through `epoll_poll_op()`.
5. `EPOLLEXCLUSIVE` is rejected with `EINVAL` on `EPOLL_CTL_MOD`.
6. Edge-triggered polling (`EPOLLET`) suppresses repeated level notifications
   until state changes or new data arrives.
7. One-shot polling (`EPOLLONESHOT`) delivers an event once and disables
   subsequent notifications until rearmed with `EPOLL_CTL_MOD`.
