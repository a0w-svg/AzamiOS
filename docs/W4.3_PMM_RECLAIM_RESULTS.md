# W4.3 deferred physical-page reclaim — 2026-10-11

Allocation failure now publishes a zone mask for a pre-created kernel worker.
The worker returns remote CPU cache pages through the existing by-value RPC
mechanism. The failing allocation still returns zero; subsequent allocation
attempts can use the returned frames. No cache size, refill batch or allocation
order preference changes are included.

The added failure hook only performs an atomic OR, including when a caller
holds a heap/VMM lock with interrupts disabled. General failures select both
zones; DMA32 failures select only that zone. The worker is allocated after
`sched_init()` and before the opt-in pressure test or scheduler activation;
startup failure is reported to the boot caller and in read-only counters.

Each sweep considers at most eight rotating CPU IDs and reserves at most 256
pages across RPC attempts, including requests that can complete after timeout.
Each owner callback has a 32-page cap, disables local interrupts and tries the
global allocator lock once. When both zones are requested, each gets at most
16 pages. A busy lock returns without draining. Callback text, cache rows and
by-value payload storage survive caller timeout; no caller pointer is retained.

Receiver waits use a 10ms clock deadline within a 50ms sweep deadline, plus the
existing finite RPC spin cutoff when timekeeping stops advancing. xAPIC dispatch
now also has a 4,096-poll busy limit with incoming interrupt state restored;
x2APIC uses one architectural ICR write. Self/remote selection and dispatch run
under one interrupt guard so scheduler migration cannot change that decision.
Legacy IPI send APIs retain their existing contracts.

The worker polls every ten scheduler ticks, nominally 100ms. A fresh zone
notification permits `ceil(CPUs/8) * 8` best-effort sweeps, including the first:
eight on the tested one/four-CPU guests and 64 at the 64-CPU limit. Persistent
cache refills, busy locks and unavailable receivers spend this allowance. After
it expires, the worker stops retrying even if caches remain nonempty. A later
allocation failure rearms its zone. Separate retry state preserves fresh
failure notifications arriving during a sweep. These are attempt-count bounds;
scheduling delays and RPC work prevent an exact elapsed-time guarantee.

`/proc/pmm_reclaim` is an Azami extension with mode 0444 and no writable controls.
Its counters are independently atomic, so concurrent snapshots are approximate.
`pressure_batches` counts consumed fresh notifications; `sweeps` also counts
retries. `reclaimed_pages` counts actual frame returns, including late callbacks,
and `pending_zones` includes fresh and retry work.

The [compact evidence](../tests/bench/results/2026-10-11-pmm-reclaim.json) records
the final immutable kernel and relevant source hashes. Raw images and logs stay
local under `/tmp/azami-reclaim-epoch/`, with reproduction commands in
[the benchmark guide](../tests/bench/README.md).

The parked boot test now proves real general/DMA32 failure publication with
interrupts disabled, production draining of the stranded CPU1 page, exact public
allocation of that same frame, and complete capacity/order restoration. The
separate stock-musl payload proves scheduled worker execution, proc lookup,
enumeration, write rejection and subsequent idle cycles. It does not treat
independently read counters as a transactional snapshot.

Two KVM allocation-regression logs contained records interrupted by DHCP output
and were rejected without log repair. The final KVM run waits eight seconds for
the existing five one-second retries to finish, then execs the identical
benchmark. This is an integrity regression, not a timing comparison; the settle
delay and rejected runs are recorded in the compact evidence.

Gemini reviewed the source through Antigravity. Its persistent-pressure concern
led to expiring retry epochs. Reserved failed-attempt budgets and one visit per
CPU are deliberate limits; reclaim need not consume every available budget.
A zero fair-share quota is unreachable through the production caller, which
always issues 32-page requests. Independent review additionally fixed zone
starvation, unbounded xAPIC busy polling and migration during RPC dispatch.

Native hardware remains additional coverage. Normal
zone behavior above 4GiB is checked only with hosted cache stubs. This checkpoint
does not establish concurrent high-order coalescing, allocator throughput gains,
or guaranteed recovery under repeated receiver/lock failures. Explicit retry
for callers able to release/revalidate locks, refill/spill measurement, user-copy
faults and COW/shootdown stress remain later plan steps.
