# W4.2 scoped and remote counter checkpoint — 2026-10-07

This checkpoint adds CPU-scoped, CPU-wide and other-task counting, with bounded
remote PMU read/control. It follows the historical
[thread counter checkpoint](W4.2_COUNTER_RESULTS.md). The subsequent
[PMU/stock-tool checkpoint](W4.2_HARDWARE_RESULTS.md) adds induced KVM wrap,
privilege filters and attached stock `perf stat`; evidence here is historical.
Sampling, event groups, inheritance, enable-on-exec and multiplexing remain
explicitly unsupported.

Events accept `pid=0` or a live Linux TID, with `cpu=-1` or an online CPU filter.
`pid=-1` requires an online CPU and counts that CPU's context, including idle
for software clocks. Task enabled time includes scheduled execution on any CPU;
running time additionally excludes CPUs outside the filter. Disabled intervals
freeze; RESET clears only the count; target retirement preserves the final
readable value. Remote raw counters are read only on the CPU owning the interval.

## Request ownership

`arch/x86_64/cpu/smp_rpc.c` provides one fixed 128-byte request slot per CPU.
It copies arguments/results by value and tags each request with a generation.
Perf requests contain an event ID, operation, deadline and scalar result, with
no task, event, file or caller-stack pointers. The IRQ callback resolves the ID
under a nonblocking perf try-lock, and PMU synchronization also uses a try-lock.
Migration or contention causes a bounded retry on the current owner. Deadline
reads use an eight-attempt clock snapshot, so a stalled timekeeper publisher
cannot turn the IRQ callback or deadline loop into an unbounded seqlock wait.

| State when the sender times out | Ownership/result |
| --- | --- |
| Queued | Cancellation frees the slot; a stale IPI cannot claim the old generation. |
| Running | The receiver retains the static slot until its callback completes; sender storage may disappear immediately. |
| Completed | Completion wins cancellation; sender consumes the published result before freeing the slot. |

Perf operations use a 250 ms monotonic deadline, plus finite iteration limits.
A deadline returns `ETIMEDOUT`; a full RPC slot returns internal `EBUSY` and is
retried within the same deadline. A started callback may complete after its
sender times out; timeout cannot forcibly undo an already-started operation.
Storage remains safe in that case. Callbacks must be bounded, nonblocking and
reside in permanent kernel text. There are no dynamically accumulating requests.
The legacy `smp_call_function*` API retains its existing acknowledgment behavior.

Attachment validates the target while holding the scheduler lock, records only
persistent IDs, and publishes the internal event under the perf lock. A new
file remains privately owned until initial remote enable succeeds; failed opens
release it before publishing any descriptor. Close/exit racing a delayed callback
cannot turn an old request into access to a freed or newly allocated event.

## Affinity and permissions

The probe exposed a prerequisite bug: Linux affinity syscalls changed every
thread in the process and could return on a disallowed CPU. They now resolve a
TID under the scheduler lock, change only that thread, check `CAP_SYS_NICE` or
matching owner credentials, and migrate a self-target before returning. User
fork/clone inherit the creating thread's mask. Tests verify effective CPU
selection, explicit sibling-TID lookup, and independent caller/worker masks.
Migration metadata used by perf attachment is atomic.

`perf_event_paranoid` stays at default 2. Effective `CAP_PERFMON` or
`CAP_SYS_ADMIN` bypasses perf scope checks. Other-task attachment otherwise uses
matching real/effective/saved UID/GID values, a dumpable target and a permitted
capability subset, or `CAP_SYS_PTRACE`. That last capability does not bypass
paranoid restrictions on kernel or CPU-wide counting. A same-process attachment
remains allowed after dropping capabilities. Sysctl writes require `CAP_SYS_ADMIN`.

`PR_GET_DUMPABLE`/`PR_SET_DUMPABLE` now maintain actual process state, validate
values, inherit through fork, clear on effective UID/GID or filesystem-ID changes,
and reset on successful ordinary exec. Failed exec preserves it. Unprivileged
ptrace attachment also honors this state. No set-ID/file-capability exec support
is claimed. Tests exercise different UIDs, non-dumpable and more-privileged targets,
root with dropped capabilities, and `CAP_SYS_PTRACE`/`CAP_PERFMON` separately.

idle, CPU-wide PMU instructions, other-task clocks, remote live read/reset/disable/

output; logging after a read must not enter the reference interval.

changing scheduling or legacy calls. The timeout probe exercises all four
