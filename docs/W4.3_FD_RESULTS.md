# W4.3 FD reference and sysfs pagination checkpoint — 2026-10-07

Nonfinal temporary file references now release without acquiring the global VFS
namespace lock. `fcntl` pins descriptions while accessing them and reserves a
new reference before installing a duplicate. The indexed sysfs iterator also
fixes the directory cap found by Gemini through Antigravity. These are bounded
changes in the [measured kernel milestone](IMPROVEMENT_PLAN.md#w43--optimize-measured-bottlenecks).

## File lifetime and locking

`fget` still loads the pointer and increments its reference under `fd_lock`.
`vfs_put` uses sequentially consistent CAS only while the count exceeds one;
a successful decrement returns immediately without dereferencing the file
again. A competing close may free it immediately afterward. If the caller owns
the last reference, the unchanged namespace-locked finalizer performs teardown.
The CAS loop is lock-free, not wait-free. This change does not remove descriptor
lookup locking or require deferred reclamation.

File-dependent `fcntl` commands now use `fget`/`fput` on every path. GETFD/SETFD
access slot flags under the FD-table lock. Duplicate installation first reserves
its owned reference; a failed install releases it through `fput`, allowing
proper final teardown if a concurrent close removed the original descriptor.
Temporary I/O and fcntl references now preserve locks. Existing explicit-close
PID ownership and flock/POSIX-record-lock conflation remain limitations; this
checkpoint does not claim complete Linux lock ownership semantics.

The static musl lifetime probe checks lowest free FD selection, independent slot
flags, shared file status, full-table failures and endpoint-leak cleanup. Three
pinned readers perform 12,000 duplicate operations against concurrent close and
dup2. Thirty-two pipe-read/last-descriptor-close races have an observable oracle:
a successful write after the read descriptor is closed proves an in-flight read
owns the final reference; EPIPE after join proves it released that endpoint.
At least one such case is required. The same probe on the immutable old kernel
terminated at the cross-process lock handoff without a complete verdict and was
rejected after the bounded host timeout; its raw reproducer log is retained.
Cross-process flock checks verify temporary
references preserve ownership and final same-process close releases it.

## Fixed-count measurements

The same static payload runs 20,000 checked eventfd write/read pairs per worker,
with one or four pinned workers. Each warms up 256 pairs outside timing, followed
by one discarded full round and ten measured rounds. Every transfer, checksum,
affinity installation, thread join and child exit is checked. CPU fields record
requested affinity; the installation result is verified. Four processes use
separate FD tables, while four threads share one. Neither baseline nor optimized
measurements ran alongside other QEMU tests.

Rows report median **slowest-worker ns per write/read pair**, with MAD. Worker
timers are independent, so this metric does not measure group makespan or
aggregate throughput. Guest configuration: q35, BIOS, four vCPUs, 1536 MiB;
KVM uses `host`, TCG uses `max,+rdrand,+rdseed` with multithreaded translation.

| Accelerator / mode | Before median ± MAD (ns) | After median ± MAD (ns) | Reduction |
| --- | ---: | ---: | ---: |
| KVM / one thread | 397.26 ± 0.85 | 361.98 ± 2.53 | 8.9% |
| KVM / four threads | 592.91 ± 33.41 | 490.05 ± 16.44 | 17.3% |
| KVM / four processes | 482.30 ± 23.72 | 422.11 ± 20.45 | 12.5% |
| TCG / one thread | 1968.09 ± 30.14 | 1812.97 ± 9.46 | 7.9% |
| TCG / four threads | 6720.89 ± 246.19 | 1990.77 ± 95.04 | 70.4% |
| TCG / four processes | 7069.92 ± 222.43 | 1942.57 ± 40.77 | 72.5% |

Repeating the immutable old KVM kernel after the optimized run produced
371.74 ± 1.70 ns (one thread), 545.54 ± 18.20 ns (four threads), and
479.54 ± 22.95 ns (four processes). Host drift therefore affects the first
serial result. The optimized four-thread result remains 10.2% lower than the
repeat baseline, exceeding their combined MAD; four-process reduction remains
12.0%. These are measurements on this host, not a portable physical-machine
performance guarantee. TCG establishes emulated execution behavior.

The broader unchanged W4.1 suite used 100,000 getpid calls, 1,000 pipe round
trips, 64 MiB mappings and 100 fork/wait pairs, each with ten repetitions:

| Pipe round trips | 52.52 ± 0.57 | 50.69 ± 1.58 |

The initial getpid median rose 5.7%, within combined MAD. A complete suite repeat

or regression is established. Memory timings include eager allocation and first
touch, as documented by W4.1. No allocator tuning was made.

## Sysfs pagination and external review

Gemini's W4.2 review found the real 32-entry fallback array cap. An immutable
pre-fix kernel boot detected 32 CPUs but enumerated only CPU0–CPU25, failing the
exact-enumeration check. CPU, class, block and device directories now emit pages
from their live indexed registries, without a temporary directory-size cap.
Reserved legacy class/device names are emitted once. Lookup and PMU formats
retain their behavior.

The fixed kernel enumerates all 32 and 64 requested CPUs. An 80-byte CPU buffer
requires 19 and 35 successful pages respectively; the probe checks rewind,
d_off continuation cookies, repeated EOF, duplicate rejection, direct topology
and metadata lookup. The runner requires actual present and enumerated counts
to equal requested vCPUs. Other dynamic directories have continuation tests,
but this guest does not populate more than 32 block/class/device entries.

Gemini 3.1 Pro reviewed code through the user-authorized Antigravity CLI using
read-only, tool-free source bundles. W4.2's buffer-copy and off-CPU timing claims
were rejected using the real caller and live Linux evidence; its pagination
finding was reproduced and fixed. Its further FD/sysfs review confirmed the
reference balance and continuation cookies. The reported shared-FD spinlock
contention is intentional benchmark coverage. Explicit close still uses the old
locked finalizer, so the hypothetical migrated-close lock leak does not apply.
The reported unsynchronized F_SETFL is a pre-existing status-flag limitation;
fcntl lifetime pinning does not claim to serialize concurrent flag updates.
Coherent flag handling across fcntl/ioctl remains separate work.
Local review removed a misleading aggregate-throughput calculation and verified
that saved before-kernel source attribution is separate from the worktree at
launch. The measured payload stayed byte-identical.
