# W3.8 path confinement checkpoint — 2026-10-06

`openat2` now applies resolve constraints while walking directory objects and
opens the resulting dentry in the same operation. The separate lexical-prefix
and symlink prechecks are removed. A counted dirfd reference survives concurrent
close/reuse; `BENEATH` rejects absolute paths/links and root escapes; `IN_ROOT`
rebases absolute paths/links and clamps `..`; `NO_SYMLINKS` and `NO_MAGICLINKS`
are enforced at each encountered link. Missing or nondirectory components
before `..` retain their Linux errors rather than disappearing during path
normalization. Trailing slashes require a directory.

The walk shares a recursive, sleepable topology guard with open/create,
mkdir/mknod/link/symlink, unlink/rmdir/rename, mount/umount, and procfs PID
removal. Cwd/root changes use the same guard, so AT_FDCWD opens take a coherent
filesystem-view snapshot. The guard permits filesystem I/O and callback reentry on the same
thread; it is never a spinlock held over I/O. It currently serializes these
metadata operations globally. Finer-grained locking and positive dentry cache
reclamation remain future work; no performance optimization is claimed.

Rename preserves directory object identity and cached child parent chains, so
an existing directory FD follows its directory when moved. Cross-filesystem
and descendant-directory renames are rejected before filesystem callbacks.
Ext2 open descriptions retain unlinked inodes and blocks until final close;
stat reports the real zero link count. Tmpfs removed directories also report
zero links. The threaded suite exposed another existing defect: `exit(2)` from
a pthread closed the process's shared FD table. Process cleanup now runs when
there are no live siblings; `exit_group` continues to mark all siblings first.

`open_how` validates flags/modes/pointers, accepts zero-filled extensions,
rejects unknown nonzero extension bytes with `E2BIG`, and rejects unsupported
known modes with `EOPNOTSUPP`. Creation applies umask and CLOEXEC. Read-only
`O_TRUNC` behaves like Linux and errors from filesystem open/truncate propagate.

This is a partial Linux implementation. `NO_XDEV`/`CACHED`, `O_PATH`,
`O_TMPFILE`, direct/asynchronous/synchronous I/O modes, and access mode 3 remain
unsupported. Scoped walks through ambiguous mount-parent chains fail closed
with `EXDEV`. The existing 512-byte VFS path buffers and legacy path handling
in other syscalls remain limits. General Linux mount identity, cache eviction,
and full DAC/ACL conformance are outside this checkpoint. W3.8 remains in
progress; exact interpreter loading and exec failure handling are next.

from a sandbox without `/dev/kvm`, and remain historical evidence. Host-context
runs use `-enable-kvm -cpu host`; sandbox runs use TCG. This checkpoint's KVM
benchmark uses the updated kernel, QEMU 10.2.2/q35, BIOS, four vCPUs, 1536 MiB,
an AMD Ryzen 7 8845HS CPU, and reported monotonic resolution of 1 ns. Its kernel
SHA-256 is `f856d33c627a536ec38982d8a7f394ee6904c174150776fbff704fd78553a33f`.

These are a new KVM baseline, not before/after speedup measurements. They do
not provide an equal-workload, equal-hardware OS comparison with the original
TCG/Linux baselines. Mapping and touch costs are both included. Raw samples,
timings, counts, source fingerprints, and machine/artifact hashes are retained.
The benchmark ran after the other VM gates finished.

The final futex stress log contains one TLB shootdown IPI retry during
process teardown after its zero-failure verdict. An earlier run logged three
retries before completing. These diagnostics are retained; a passing probe
does not by itself verify post-verdict teardown. A separate 12-second KVM
observation also passed all five groups and logged a single teardown retry,
with no repeated diagnostic before the observation ended; acknowledgments
were not instrumented. No such retries occurred in the path suites or boot
matrix. This does not establish a general TLB/SMP audit. Broad header builds
also expose existing MKDEV/MAJOR/MINOR redefinitions, an unused evdev lock,
and the ptrace USER_ADDR_MAX redefinition. Focused changed sources build cleanly.
