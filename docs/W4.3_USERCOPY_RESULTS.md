# W4.3 user-copy fault observations — 2026-10-11

The [2026-10-12 transaction checkpoint](W4.3_USERCOPY_FIX_RESULTS.md) fixes all
39 differences below and adds argument/page-sized and device checks. This
document retains the original before-change evidence.

The same unmodified static-musl binary now measures 60 small I/O cases on real
Linux and four-CPU KVM/TCG AzamiOS guests. Both guests produce identical
observations: 21 match Linux and 39 differ. This is a baseline of remaining
compatibility defects, not a passing syscall-conformance or copy-speed result.
The [compact evidence](../tests/bench/results/2026-10-11-usercopy-faults.json)
contains every case, the host release, and exact payload/kernel hashes.

Each case creates a fresh memfd or nonblocking pipe and maps private pages.
Scalar reads/writes cross a 4KiB boundary with 1, 16 or 63 valid bytes before
PROT_NONE, a read-only page, or an unmapped page. Other cases cover a fault in
later vector payload, a fault in the second vector descriptor, zero scalar
length, zero vector count, a nonzero request with NULL data, and valid controls.
Read-only source pages remain readable; the oracle captures that distinction.

The probe records the syscall result/errno, regular-file position, stored or
remaining data count and weighted checksum, copied prefix, and an eight-byte
preceding canary. Read data is seeded in one 128-byte write, making the pipe
buffer boundary deterministic without assuming Linux's pipe capacity. Every
case closes its handles and releases its mappings. No comparison depends on
addresses, timing, guest PID1 identity, or concurrent writers.

| Case | Linux observation | AzamiOS observation |
|---|---|---|
| memfd read 32 bytes, second 16 inaccessible | Returns 16; file position 16 | `EFAULT`; position 32, despite 16 copied bytes |
| memfd write, same boundary | Returns 16; stores 16 bytes | `EFAULT`; stores zero bytes |
| pipe read, same boundary | `EFAULT`; all 128 pipe bytes retained | `EFAULT`; 32 pipe bytes consumed |
| memfd readv, second descriptor inaccessible | `EFAULT`; position zero, destination untouched | `EFAULT`; position eight, eight destination bytes changed |
| pipe writev, valid eight bytes then bad payload | `EFAULT`; pipe remains empty | Returns eight; eight bytes committed |
| zero iovec count with bad descriptor pointer | Returns zero | `EINVAL` |
| pipe read with NULL and count one | `EFAULT` with data retained | Returns zero |

All observed preceding canaries remain intact. That limited result does not
prove SMAP restoration, exception-entry AC handling, concurrent unmapping,
all device/file types, large transfers, or COW isolation.

Source inspection explains the measured failures. Scalar reads call `vfs_read`
before `copy_to_user`; a failed copy therefore follows pipe consumption or a
file-position advance. Partial copied bytes are not reported. Scalar writes
discard the copied prefix on a copy fault. Vector syscalls import each descriptor
just before processing it, so a later descriptor fault can follow earlier I/O.
They also split pipe vectors into scalar transactions. The early argument checks
reject zero vector counts and return zero for nonzero NULL scalar requests.

The runner requires all 60 named records in order, complete collection verdicts,
typed fields and consistent errno/data metadata. It compares every observation
field with the Linux result. Its default exit status is failure when differences
exist; `--collect-only` explicitly saves a baseline and returns collection
success while retaining `compatible: false`. The guest's 60-collection verdict
only confirms that the measurement harness completed. Seventeen corrupt-log
variants are rejected for each Linux/KVM/TCG profile, and a single changed file
position is detected even when the syscall result is unchanged.

Reproduce after building `tools/linux` and the kernel:

```sh
make -C tools/linux usercopy-observe-probe
python3 -B tests/bench/usercopy_observe.py --accel kvm tcg --collect-only \
    --kernel build/kernel.elf --output /tmp/azami-usercopy-baseline
python3 -B tests/bench/test_usercopy_observe.py \
    /tmp/azami-usercopy-baseline/kvm/serial.log
```

Raw logs, disposable images and immutable binaries remain local under
`/tmp/azami-usercopy-final/`; no raw artifacts are committed. Next work should
import and validate vector descriptors before side effects, introduce a
user-aware pipe transaction that commits only accepted bytes, and preserve
partial-copy results and regular-file positions. The corpus needs invalid-FD,
length/overflow, page-sized transfer, concurrent mapping/COW and SMAP-entry
extensions before selecting copy thresholds or claiming full Linux semantics.
