# W4.3 user-copy transaction fixes — 2026-10-12

The 60-case [fault baseline](W4.3_USERCOPY_RESULTS.md) previously differed from
Linux in 39 cases. The final kernel matches all 60 on both KVM and TCG. An
additional 84 argument/page-boundary observations and 14 device/descriptor
checks also match the same stock-musl binaries running on Linux. The
[compact evidence](../tests/bench/results/2026-10-12-usercopy-fix.json) preserves
all compared observations, kernel and payload hashes, source hashes and gates.
These are bounded correctness results; no copy-speed improvement is claimed.

## Implementation

Scalar/vector I/O pins the file description and checks its access mode before
payload arguments. Closed standard descriptors return `EBADF`, including zero
length requests. Initial console stdout/stderr now open for writing. Eventfd,
timerfd, signalfd and fanotify descriptions retain read/write access modes.

Vector I/O snapshots all descriptors before any backend or payload operation,
validates lengths/ranges, accepts zero vector counts, and caps total transfer
size at Linux's `MAX_RW_COUNT`. One iterator preserves accepted byte counts
across vectors. NULL nonzero requests reach the user-copy fault path.

Ordinary memfd, tmpfs, ext2, FAT32 and SquashFS operations explicitly opt into
prefix handling. Reads use a local offset, copy outside backend locks, then
compare/exchange the shared file position by the accepted byte count. A
conflicting reader retries rather than restoring an obsolete position. Writes
submit the successfully copied prefix. Existing 4KiB stack/64KiB allocation
limits remain. Structured devices preserve whole-buffer staging and their
existing per-vector operation sizes.

Anonymous pipes provide user-aware callbacks. Reads snapshot the ring under
its spinlock, copy with the lock released, and commit only if the read generation
still matches. Copy faults retain readable bytes. Writes stage a complete
transaction outside the lock; requests at most 4096 bytes commit atomically
across vectors and ring wrap. Larger requests can return already committed
chunks. Conditions, space and reader existence are rechecked after copying;
nonblocking `EAGAIN`, signals and waiter cleanup have hosted coverage.

Antigravity CLI with Gemini reviewed the implementation. Its actionable queue
finding was fixed: enqueueing a waiter already present must not truncate later
waiters. A regression exercises the production queue helper. Review suggestions
were checked against the real Linux observations before changing semantics.

All guests use the same immutable final kernel. The I/O comparison guests use
q35, four CPUs, 1536MiB, no NIC and `quiet` kernel logging to prevent diagnostic
text from corrupting structured observations. The parsers require every named
record, its typed fields and one successful final verdict. They reject 17/20
corrupt variants per Linux/KVM/TCG profile. The production pipe harness passes
16 transactions with UBSan and scripted fault/scheduler interleavings. The
syscall-table verifier checks all 385 entries with zero errors.

The shared-reader probe preloads 4096 numbered 64-bit records, forks four
children on distinct available CPUs and synchronizes their first reads. Children
share one open file description and transfer 64-byte result batches through a
nonblocking pipe. The supervisor checks count, complete unique records, each
reader's contribution and every child exit; failures have bounded kill/reap
cleanup. It counts records rather than waiting for process teardown to close
pipe writers. A single-CPU negative control and a stalled-child control fail.

## Reproduction

After preparing the stock musl toolchain and kernel:

```sh
make -j8 build/kernel.elf
make -C tools/linux usercopy-observe-probe usercopy-compat-probe \
    usercopy-device-probe usercopy-shared-probe
LINUX_TEST_CMDLINE=quiet python3 -B tests/bench/usercopy_observe.py \
    --accel kvm tcg --kernel build/kernel.elf --output /tmp/azami-usercopy-fixed-base
LINUX_TEST_CMDLINE=quiet python3 -B tests/bench/usercopy_compat.py \
    --accel kvm tcg --kernel build/kernel.elf --output /tmp/azami-usercopy-fixed-extension
python3 -B tests/bench/test_usercopy_observe.py /tmp/azami-usercopy-fixed-base/linux.txt
python3 -B tests/bench/test_usercopy_compat.py /tmp/azami-usercopy-fixed-extension/linux.txt
python3 -B tools/tests/pipe_transaction_test.py
UCOPY_OBSERVE_EXIT=1 tools/linux/out/bin/azami-usercopy-device
USERCOPY_SHARED_EXIT=1 tools/linux/out/bin/azami-usercopy-shared
LINUX_TEST_CMDLINE=quiet LINUX_TEST_ACCEL=kvm LINUX_TEST_NET=none \
    LINUX_TEST_WORK=/tmp/azami-usercopy-device scripts/linux-test.sh \
    tools/linux/out/bin/azami-usercopy-device
LINUX_TEST_CMDLINE=quiet LINUX_TEST_ACCEL=kvm LINUX_TEST_NET=none \
    LINUX_TEST_WORK=/tmp/azami-usercopy-shared scripts/linux-test.sh \
    tools/linux/out/bin/azami-usercopy-shared
```

Repeat the two guest probes with `LINUX_TEST_ACCEL=tcg` and fresh work paths.
The strict comparison runners fail on any observed difference. Raw logs and
images remain local under `/tmp/azami-usercopy-verified/`. The implementation
was isolated from concurrent shared-checkout edits in the
`checkpoint/2026-10-12-usercopy` worktree; binaries and disk images are excluded
from the commit.

## Limits and next work

Pipe fault cases seed one Linux pipe buffer; AzamiOS uses a flat 4096-byte ring
without Linux's buffer provenance. Results do not establish all multi-buffer
partial-fault semantics. Optimistic read retries can rewrite destination bytes
before their eventual commit or failure. The shared-reader result covers
64-byte reads; it does not establish whole-call serialization for larger,
chunked reads, shared writes, `lseek` or positional I/O. `pread`/`pwrite` retain
existing shared-position handling and require a separate checkpoint.

The tested Linux host does not serialize a directly created memfd's shared
position in the same way as an ordinary regular-file open. The shared probe
therefore uses an ordinary file by default. `USERCOPY_SHARED_MEMFD=1` selects
optional additional stress and is not a matching Linux concurrency oracle.

Structured-device reads retain their existing consumption on copy failure.
Socketpair/AF_UNIX wrappers do not yet have these user-aware pipe callbacks.
Concurrent `mprotect`/`munmap`, COW isolation, fatal-thread teardown during
faults and complete SMAP/exception-entry restoration remain additional work.
The [small/large I/O baseline](W4.3_USERCOPY_TIMING_RESULTS.md) now records
end-to-end memfd timings; isolated-copy timing remains required before
selecting ERMS/vector thresholds.
QEMU results provide guest execution evidence; physical hardware and complete
Linux I/O conformance remain unvalidated.
