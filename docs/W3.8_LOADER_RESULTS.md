# W3.8 native dynamic loader checkpoint — 2026-10-06

The native loader adds recursive futex serialization of public entry points,
constructor reentrancy, reverse destructor-array order, transitive symbol lookup,
`dladdr()`, and rollback of newly mapped objects when runtime loading fails.
`libc` calls the loader finalizer through `__libc_ldso_lookup()` during `exit()`;
`_exit()` and signal termination do not run that hook.

The runtime fixture covers repeated loads, dependency teardown, nested loading
from constructors, symbol lookup, rejection of unresolved symbols and newly
introduced runtime TLS, and loading a valid object after those rejections.
Startup static TLS is supported; new runtime `PT_TLS` objects are rejected.
`dladdr()` first finds the containing load segment, then reports the nearest
preceding defined symbol. It does not require symbol-size containment.

The historical run reported 53 assertions passed and zero failed under KVM:
15 repeated-load/dependency assertions, 6 destructor-order assertions,
7 constructor-reentrancy assertions, 12 lookup/address assertions,
6 rollback assertions, 6 error-isolation assertions and 1 worker-stress assertion.
The raw loader log was not retained with the checked-in evidence, so this is a
recorded result rather than a freshly reproducible evidence claim. The fixture
is built by `make -C userland dynlink` and `/etc/run-dynlink-test` enables the
native init boot checks, including `/bin/dltest_runtime.elf`.

The four-worker fixture reports load/call/unload errors over 80 cycles. It does
not check thread creation/join return values and does not establish freedom from
data races. The mutex owner field currently has accesses outside the mutex;
error storage has 16 TID slots which are not reclaimed and shares slot zero
after exhaustion. These remain follow-up work. Rollback fixtures establish
subsequent usability, not exact physical-memory or descriptor leak accounting.
The recorded semantic regression gates are listed in the individual W3.8 and
W4 checkpoint documents; they do not prove absence of all regressions.

The associated e1000 and rtl8169 changes move receive staging buffers from
kernel stacks into static storage. Their respective receive-draining guards
serialize use while packet delivery temporarily releases the spinlock. This
reduces receive-stack pressure; it is not new hardware interoperability evidence.
