# AC'97 playback

The AC'97 driver supports the I/O-port register layout used by Intel 82801AA
(8086:2415), 82801AB (8086:2425), 82801BA (8086:2445), 82801CA (8086:2485),
and 82443MX (8086:7195). It selects the primary codec and stereo signed
16-bit little-endian PCM. MMIO-only controllers and non-Intel AC'97 register
layouts are not covered by this driver. The sound core exposes its first
registered card as `/dev/dsp` and `/dev/audio`.

Initialization waits for the codec, serializes codec accesses with the hardware
semaphore, and enables variable-rate audio when advertised. Rate requests are
limited to 8000–48000 Hz and read back from the codec. Fixed-rate codecs report
48000 Hz. A rate change while DMA is playing returns `EBUSY`; reset or let the
queue drain first. PCM output gain is fixed at 0 dB, while the existing desktop
volume control adjusts master volume. Zero volume sets hardware mute.

## DMA submission

The driver allocates 32 page-sized PCM buffers and a descriptor list below
4 GiB. Each write snapshots the consumer index, fills available descriptors,
orders the memory writes, then publishes the batch with one LVI port write.
Only the first submission after reset needs a start command. Buffer physical
addresses are initialized once. No completion interrupts are generated because
the submission path obtains capacity directly from CIV.

The current hardware descriptor is never overwritten. Once playback drains,
new submissions resume at the next descriptor, preserving the hardware's
prefetch sequence. A running or drained ring conservatively reserves CIV;
a reset ring can initially accept all 32 buffers. Writes return short counts
when capacity is limited and `EAGAIN` when full. They accept complete 4-byte
stereo frames; an incomplete trailing frame remains unwritten, and a nonempty
write smaller than one frame returns `EINVAL`.

## Linux OSS controls

The driver implements these Linux x86_64 OSS requests, using the standard
integer argument layouts:

- `SNDCTL_DSP_RESET`: stop/reset DMA and discard queued playback.
- `SNDCTL_DSP_SPEED`, `SOUND_PCM_READ_RATE`: negotiate/query sample rate;
  a speed argument of zero queries the current rate.
- `SNDCTL_DSP_STEREO`, `SNDCTL_DSP_CHANNELS`, `SOUND_PCM_READ_CHANNELS`:
  report the supported stereo configuration.
- `SNDCTL_DSP_SETFMT`, `SNDCTL_DSP_GETFMTS`, `SOUND_PCM_READ_BITS`:
  report signed 16-bit little-endian PCM.
- `SNDCTL_DSP_GETBLKSIZE`: report 4096-byte fragments.
- `SNDCTL_DSP_GETOSPACE`: report writable fragments and bytes using Linux's
  16-byte `audio_buf_info` layout.

The historical Azami rate and volume ioctl numbers remain supported, including
volume readback. Unsupported requests return `ENOTTY`. This is a subset of OSS:
capture, mmap, drain/sync, configurable fragments, blocking waits, and poll-based
write readiness are not implemented. Writers should handle short writes and
retry `EAGAIN`. Format/channel negotiation returns the actual supported format;
clients must inspect the returned values. User argument copies happen outside
the IRQ-disabled driver lock.

## Validation

Run the deterministic driver tests:

```sh
sh tools/tests/ac97-test.sh
```

They cover full rings, wraparound, starvation/restart, frame alignment, batching,
rate/volume/format ioctls, user-copy faults, hardware timeouts, BAR validation,
all 33 DMA allocation failure points, and device removal.

Run the end-to-end test with QEMU, xorriso, mke2fs, Python, and the repository's
musl toolchain (`make -C tools/linux toolchain`), plus host Linux UAPI headers:

```sh
sh tools/tests/ac97-qemu-test.sh
```

The script builds the kernel and a stock Linux OSS client, boots an isolated ISO
on a four-vCPU Q35 VM, and records playback through QEMU's WAV backend. It checks
44.1 kHz negotiation and two 8192-frame stereo bursts separated by starvation,
including channel ordering, amplitudes, and frame counts. Logs, ISO, and audio
remain in the printed `/tmp/azami-ac97-qemu.*` directory. The existing OS disk
image is not used. Physical controllers still need hardware validation.
