# W3.8 namespace checkpoint — 2026-10-06

The namespace checkpoint is implemented. W3.8 remains in progress: VFS path
confinement, interpreter/exec failure handling, and runtime-loader fidelity are
still pending. The next checkpoint is `openat2` confinement during traversal.

Previously, `unshare` reported success for namespaces with no isolation,
`clone(CLONE_NEWUTS)` bypassed the capability check, UTS pointers and names were
read without lifetime/synchronization protection, and procfs exposed one UTS
identity for every process. Empty names also fell back to global defaults.

The implementation now pins each process's UTS reference under the scheduler
lock, copies names under a namespace lock, and allocates a unique identity for
each new namespace. Fork preserves sharing; clone/clone3 with `CLONE_NEWUTS`
create an isolated copy; exec preserves it. Creating a UTS namespace and
changing names require `CAP_SYS_ADMIN`. Hostname/domain writes accept 64 bytes,
preserve empty and embedded-NUL values, and reject invalid pointers. Procfs
returns the actual UTS identity, pins the target process and namespace, and
rejects stale links after reaping. `pid_for_children` shares the global PID
identity with the correct `pid:[...]` link format.

Unsupported isolation fails before changing resources:

| Operation | Supported behavior and limits |
| --- | --- |
| `unshare(0)` | Success without a state change |
| `unshare(CLONE_NEWUTS)` | Supported for a process with no live sibling threads; live siblings return `EOPNOTSUPP` |
| `clone` / `clone3` with `CLONE_NEWUTS` | Process UTS isolation; combining it with `CLONE_THREAD` returns `EOPNOTSUPP` |
| PID, mount, IPC, network, user, cgroup, time namespaces | Unsupported: `EOPNOTSUPP`, or `EPERM` when the required capability is absent |
| `unshare(CLONE_FS/CLONE_FILES)` | `EOPNOTSUPP`; the kernel has no separate per-thread resource tables |
| Mixed supported/unsupported unshare flags | Failure leaves namespace state unchanged |
| `setns` | Invalid FD returns `EBADF`; ordinary FD returns `EINVAL`; namespace descriptors/joining are still unsupported |

Global identities for the other procfs namespace links describe shared global
resource domains. They do not provide usable namespace file descriptors or
prove container compatibility. Full PID translation, mount isolation, user
namespaces, and per-thread namespace storage remain future work. The generated
syscall status now marks clone/clone3/unshare/setns partial and explains that
source presence is not Linux conformance evidence.

The ABI gate intermittently timed out at `pthread_join` during this work. A
code audit found a futex value-check/enqueue gap that could miss thread exit,
and a wake could be lost across preemption before sleeping. Futex waits now
publish before rechecking the value and use a stable wake predicate checked
under the scheduler lock. Requeued waiters are removed from their destination
bucket before their stack entry goes out of scope. The original failed gate
log is retained; subsequent ABI gates and the dedicated stress suite pass.
